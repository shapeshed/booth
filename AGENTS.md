# AGENTS.md

Guidance for future agents working on Booth.

## Project

Booth is a local-first Android podcast player built with Kotlin, Gradle, Jetpack Compose, and
Material 3. The package/application id is:

```text
com.shapeshed.booth
```

Use JDK 17. The app compiles with Android SDK 37, targets SDK 37, and has a minimum SDK of 26.

## Common commands

Build and install a debug build:

```sh
./gradlew installDebug
```

Run the normal quality gate:

```sh
./gradlew quality
```

Build the production-like, debug-signed variant for device testing:

```sh
./gradlew installProductionDebugKey
```

Run isolated instrumentation tests without deleting the normal installed app or its data:

```sh
./gradlew preservingDebugAndroidTest
```

For a personal device, use a dedicated Android test device or secondary Android user/profile and
select it explicitly with `ANDROID_SERIAL`:

```sh
ANDROID_SERIAL=<test-device-serial> ./gradlew preservingDebugAndroidTest
```

Instrumentation uses the isolated `com.shapeshed.booth.deviceTest` application ID. Do not run
connected instrumentation tasks against `com.shapeshed.booth` on a device containing personal app
data. See [docs/testing.md](docs/testing.md) for the testing pyramid, UI coverage expectations,
and JaCoCo commands.

## Release versioning

Release versions use:

- Gradle `versionName`: plain semver, for example `0.1.0`
- Gradle `versionCode`: monotonically increasing integer
- Git tags: prefixed with `v`, for example `v0.1.0`

For a release, update `app/build.gradle`, review user-facing changes, and run:

```sh
./gradlew test lint assembleRelease
```

Nightlies are generated by GitHub Actions and published as a replaceable `nightly` GitHub Release.
Tagged releases build a signed APK and checksum and create a draft GitHub Release. Do not tag,
push, or publish a release unless explicitly requested.

## Signing

Android release signing uses:

```text
BOOTH_KEYSTORE_FILE
BOOTH_KEYSTORE_PASSWORD
BOOTH_KEY_ALIAS
BOOTH_KEY_PASSWORD
```

The helper script is:

```sh
scripts/create-release-keystore.sh
scripts/create-release-keystore.sh --set-github-secrets
```

Never commit keystores, passwords, signed APKs, or generated local signing files. The `local/`
directory is intentionally ignored.

## Architecture direction

- Keep the listening experience central: queue, playback progress, downloads, offline playback,
  sleep timer, and Android media controls.
- Keep subscriptions, episodes, playback state, downloads, and settings local by default.
- Use Room for durable podcast data and search indexes, Preferences DataStore for lightweight
  settings, WorkManager for refresh/subscription/download work, and Media3 for playback.
- Keep RSS/Atom parsing, URL handling, sorting, persistence mappings, search transformations, and
  playback state transitions deterministic and unit-tested.
- Keep Android and Compose concerns out of pure data transformations wherever possible.
- Keep application-scoped services explicit and test-replaceable. Hilt is now used for ViewModel
  construction and app-scoped repository/provider bindings because it provides a concrete
  maintenance and testability benefit; do not add additional abstraction without similar value.

## UI notes

- Favor a calm, minimal listening interface and direct controls.
- Prefer existing Material 3 and Material 3 Expressive patterns over custom interaction styles.
- Use adaptive layouts for phones, tablets, and other window sizes.
- Keep composables side-effect free, hoist state appropriately, forward `Modifier` to the outermost
  layout, and collect UI Flows with `collectAsStateWithLifecycle()`.
- Use stable keys and content types in lazy lists, and avoid unnecessary work during recomposition.
- Check screenshots and device behavior before changing typography, playback controls, notifications,
  edge-to-edge behavior, or navigation.

## Testing and quality

Keep parsing, URL handling, sorting, persistence mappings, search, and playback state transitions
covered by unit tests. Important Compose interactions should have UI tests. Playback changes should
be checked for pause/resume, seeking, audio focus loss, headphone disconnect, background playback,
process recreation, notification actions, downloads, and unavailable network conditions.

## Git hygiene

The worktree may contain user changes. Do not revert unrelated work. Use Conventional Commits:

```text
type(scope): description
```

Do not commit `local.properties`, build output, IDE files, keystores, signing credentials, or
generated release artifacts.
